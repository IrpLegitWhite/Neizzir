## Как это было

Процесс восстановления кода занял значительное время. Приложение использует Kotlin с агрессивной обфускацией, из-за чего JADX выдавал сотни ошибок декомпиляции на этапе первичного анализа. Многие классы были переименованы в односимвольные идентификаторы, а критическая логика вынесена в нативные библиотеки через JNI.

Основная сложность заключалась в ручном сопоставлении разрозненных фрагментов кода, восстановлении структуры пакетов и поиске связей между обфусцированными вызовами. Дополнительно пришлось разбираться с кастомной реализацией TLS-моста, который использует пиннинг сертификатов и эфемерные ключи для шифрования трафика — это потребовало отдельного анализа сетевого слоя.

В итоге удалось восстановить читаемую структуру проекта, определить ключевые точки взаимодействия с сервером и понять архитектуру лаунчера.
